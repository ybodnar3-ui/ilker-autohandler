## Точка входу

```
https://www.willhaben.at/iad/haendler/hayatgruppe/auto/?orgId=1004471&page=1&rows=200
```

- `orgId` = **1004471** — стабільний ідентифікатор дилера.
- **Весь сток повертається одним запитом**: `rows=200` → 99 з 99 оголошень.
- Час відповіді ~0.6 с, обсяг ~1.8 МБ.
- HTTP 200 зі звичайного curl зі стандартним User-Agent.
  Ні Cloudflare-челенджу, ні капчі, ні обовʼязкових кук.

**Наслідок для синхронізації:** один цикл = **один HTTP-запит**. При інтервалі
15 хв це 96 запитів на добу. Навантаження на willhaben мізерне, окремий
краулер по сторінках оголошень не потрібен.

## Формат даних

Дані лежать у `<script id="__NEXT_DATA__" type="application/json">` — сайт на
Next.js віддає повний JSON у розмітці. Ми **не парсимо HTML** і не залежимо
від верстки: ламатиметься лише при зміні структури даних, а не дизайну.

Шлях: `props.pageProps.searchResult.advertSummaryList.advertSummary[]`
Лічильник: `props.pageProps.searchResult.rowsFound`

Кожне оголошення — **57 атрибутів** у вигляді `{name, values[]}`.

## Проблеми в даних, які сайт має виправляти

1. **Заголовки засмічені SEO-спамом.** Майже кожен `HEADING` містить
   `/// FINANZIERUNG 0€ MÖGLICH ///` або подібне. На willhaben це працює на
   видачу, на власному сайті виглядає дешево. Треба вичищати при імпорті.

2. **Описи — шаблонна заглушка.** `BODY_DYN` містить однаковий текст про
   фінансування для всіх авто, а не опис конкретної машини. Тобто **на текст
   опису покладатись не можна** — унікального контенту в джерелі немає.
   Сайт має будуватись на фото + структурованих характеристиках.

3. **`CAR_MODEL/MODEL` часто `Sonstige`** («інше»), а справжня модель
   зашита в `MODEL_SPECIFICATION` разом зі спамом. Нормалізація моделі
   потребує окремої логіки.
